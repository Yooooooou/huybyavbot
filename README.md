# memebot — «Мемный вырезчик»

Телеграм-бот, который в случайные моменты времени берёт мемный ролик с YouTube,
вырезает случайный короткий отрезок аудио (5–15 сек) и отправляет его как
**голосовое сообщение**. Повторы одного и того же отрезка исключаются.

Работает **в любом чате/группе, куда его добавят** — сам запоминает чаты и рассылает
мемы во все них по расписанию. Есть команда **`/meme`** — прислать мем прямо сейчас
(проверить работоспособность). Из настройки нужен **только `BOT_TOKEN`**.

## ⚠️ Дисклеймер (честно, не прячу)

Скачивание аудио с YouTube технически **нарушает ToS YouTube**. Для приватного бота
в узком кругу друзей на практике это не отслеживается и риска почти нет, но это **не
«белая» схема**. Если хочется на 100% чисто — см. раздел «Альтернатива без YouTube»
ниже (TTS + собственные SFX, никакой привязки к чужому видео).

## Как это работает

1. Добавляешь бота в чат/группу — он автоматически запоминает этот чат
   (`chats.json`). Команда `/meme` тоже регистрирует чат и сразу шлёт мем.
2. Бот **сам ищет** мемные ролики на YouTube по ключевым словам из `queries.json`
   (через `yt-dlp`, **без API-ключа и без квот**). Ничего вручную собирать не надо.
3. По расписанию (APScheduler, случайный интервал) выбирается случайный запрос,
   из результатов — случайное видео. Слишком длинные ролики и стримы отсеиваются.
4. `yt-dlp` качает только аудиодорожку во временную папку.
5. `ffprobe` узнаёт длительность, выбирается случайная стартовая точка (не первые/
   последние 5 сек), `ffmpeg` вырезает отрезок 5–15 сек.
6. Отрезок конвертируется в формат голосового Telegram (OGG/Opus, моно, 48 кГц) и
   рассылается во **все** зарегистрированные чаты через `bot.send_voice(...)`.
7. В `sent_log.json` пишется только `{"video_id", "start_sec"}` — для дедупликации.
   Сам аудиофайл **не хранится**: временная папка удаляется сразу после отправки.

Дедупликация: если пара `(video_id, start_sec ±3 сек)` уже была — выбирается другая
точка или другое видео. Один и тот же клип за один тик рассылается всем чатам и
логируется один раз.

## Установка

```bash
pip install -r requirements.txt
```

Требуется **ffmpeg** (с `ffprobe`) в системе:

```bash
# Debian/Ubuntu
sudo apt install ffmpeg
# macOS
brew install ffmpeg
```

## Настройка

```bash
cp .env.example .env
```

Впиши в `.env` только `BOT_TOKEN` — токен от [@BotFather](https://t.me/BotFather).
Больше ничего обязательного нет: чаты бот запоминает сам, видео находит сам.

Необязательные параметры (интервал, тихие часы, длина клипа) описаны в `.env.example`.

### Важно: настройки бота у @BotFather

Чтобы `/meme` работал в группах, а бот видел, что его добавили, у @BotFather:
- **Group Privacy** можно оставить включённым (команды и события добавления всё равно
  приходят), но если хочешь — можно выключить (`/setprivacy` → Disable).
- Достаточно добавить бота в группу как обычного участника. Права админа не нужны.

## Как пользоваться

1. Запусти бота (см. ниже) — он должен быть онлайн.
2. Добавь его в любой чат/группу или напиши ему в личку.
3. Отправь `/meme` — придёт мемное голосовое (проверка).
4. Дальше он сам будет слать мемы по расписанию во все чаты, где он есть.

## Источники видео (ничего собирать не надо)

Бот сам ищет видео по ключевым словам из `queries.json`. Хочешь — поменяй/дополни
запросы там, но и дефолтных хватит. `sources.json` — **необязательный** запасной
список video_id, используется только если поиск ничего не вернул; по умолчанию пустой.

## Запуск

```bash
python bot.py
```

Бот запустится и будет ждать. Отправь ему `/meme` в любом чате — проверишь, что всё
работает, не дожидаясь расписания.

## Деплой на Railway

- Сборка идёт через **`Dockerfile`** (Railway отдаёт ему приоритет) — там ставится
  `ffmpeg` (вместе с `ffprobe`), так что нарезка/конвертация работают из коробки.
- Задай в переменных окружения проекта только **`BOT_TOKEN`** (плюс опциональные).
- Запусти **ровно один** экземпляр/реплику. Если параллельно крутятся два, Telegram
  ругается `Conflict: terminated by other getUpdates request`, и апдейты теряются.

## Реалистичные ограничения

- **YouTube и датацентр-IP.** YouTube любит блокировать скачивание с IP хостингов
  («Sign in to confirm you're not a bot»). Обходится подменой плеер-клиента (уже
  включено, `YTDLP_PLAYER_CLIENT`), а если перестанет помогать — задай `COOKIES_FILE`
  (cookies залогиненного аккаунта, формат Netscape). См. `.env.example`.
- **yt-dlp может периодически ломаться** из-за изменений на стороне YouTube. Лечится
  обновлением до свежей версии (в Docker — пересборка образа тянет актуальный yt-dlp).

## Альтернатива без YouTube (100% «чисто»)

Вместо вырезки — генерировать мем-звук самому: банк фраз (`phrases.json`) → TTS
(например Silero TTS, бесплатный локальный, хорошо с русским) → наложить заготовленный
SFX (смех, «bruh», airhorn из freesound.org) через `pydub`. Больше работы на старте,
но полностью снимает вопрос авторских прав. В текущей версии не реализовано.

## Структура

```
bot.py            # polling (команды + отслеживание чатов) + планировщик + дедуп
youtube_utils.py  # поиск видео (yt-dlp, без API) + скачивание аудио
audio_utils.py    # ffprobe/ffmpeg: нарезка и конвертация в voice
queries.json      # ключевые слова для поиска мемов
sources.json      # необязательный запасной список video_id (по умолчанию пуст)
chats.json        # чаты, куда добавили бота (создаётся автоматически)
sent_log.json     # лог отправленных фрагментов (создаётся автоматически)
requirements.txt
.env.example
Dockerfile        # образ с ffmpeg (основной способ деплоя на Railway)
nixpacks.toml     # запасной билд-конфиг (если деплоить без Docker)
Procfile          # запасной старт-конфиг (если деплоить без Docker)
```
